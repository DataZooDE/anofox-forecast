# AutoMSTL

> AutoMSTL with automatic model selection for multi-seasonality

## Signature

```sql
-- Single series
SELECT * FROM ts_forecast('table', date_col, value_col, 'AutoMSTL', horizon, params);

-- Multiple series (grouped)
SELECT * FROM ts_forecast_by('table', group_col, date_col, value_col, 'AutoMSTL', horizon, frequency, params);
```

## Description

Multiple Seasonal-Trend decomposition using LOESS with automatic model selection. Decomposes the series into trend, multiple seasonal components, and remainder. Forecasts are generated by extrapolating each component.

> **Note:** `AutoMSTL` is a documented, accepted **deprecated alias** of `MSTL` — it runs the
> exact same code path, and `model_name` reports `"MSTL"` (not `"AutoMSTL"`). When
> `seasonal_periods` is omitted, `ts_forecast_by` auto-detects a single period internally and
> uses it as the only entry — **erroring if nothing is detected** (naming `MSTL`; no default
> `[12]`). Passing `seasonal_periods` explicitly via `ts_detect_periods_agg` is still
> recommended.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `horizon` | INTEGER | Yes | — | Number of periods to forecast |
| `seasonal_periods` | INTEGER[] | No | auto-detected (single period) | Array of seasonal periods (e.g., `'[7, 365]'` for weekly+yearly); **errors if none can be auto-detected and none is given** — no default `[12]` |
| `confidence_level` | DOUBLE | No | 0.90 | Confidence for prediction intervals |

## Returns

| Column | Type | Description |
|--------|------|-------------|
| `group_col` | ANY | Series identifier (only for `_by` variant) |
| `<date_col>` | (same as input) | Forecast timestamp |
| `yhat` | DOUBLE | Point forecast |
| `yhat_lower` | DOUBLE | Lower prediction interval |
| `yhat_upper` | DOUBLE | Upper prediction interval |

`yhat_lower` / `yhat_upper` are the crate `MSTL` model's own prediction interval at
`confidence_level` (reported under `model_name = "MSTL"`) — see
[07-forecasting.md's "Prediction intervals, fitted values and input handling"](../../api/07-forecasting.md#prediction-intervals-fitted-values-and-input-handling)
for calibration caveats shared across all models.

## SQL Example

```sql
-- Step 1: Detect seasonality (aggregate form shown here; ts_detect_periods_by is an
-- equally valid alternative returning the same primary_period, see docs/api/07-forecasting.md)
SELECT product_id, round(ts_detect_periods_agg(date, quantity, 'fft').primary_period) AS primary_period
FROM daily_sales GROUP BY product_id;

-- Step 2: Forecast with detected seasonal periods — model_name reports "MSTL", not "AutoMSTL"
SELECT DISTINCT model_name FROM ts_forecast_by(
    'daily_sales',
    product_id,
    date,
    quantity,
    'AutoMSTL',
    90,
    '1d',
    MAP{'seasonal_periods': '[7, 365]'}
);
-- model_name = 'MSTL'
```

## Best For

- Data with multiple seasonal patterns at different frequencies
- Long time series with yearly and weekly seasonality
- When you need interpretable decomposition
- Retail, energy, and traffic data with complex patterns
