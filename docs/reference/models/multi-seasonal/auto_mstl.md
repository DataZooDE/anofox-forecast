# AutoMSTL

> AutoMSTL with automatic model selection for multi-seasonality

## Signature

```sql
-- Single series
SELECT * FROM ts_forecast('table', date_col, value_col, 'AutoMSTL', horizon, params);

-- Multiple series (grouped)
SELECT * FROM ts_forecast_by('table', group_col, date_col, value_col, 'AutoMSTL', horizon, frequency, params);
```

## Description

Multiple Seasonal-Trend decomposition using LOESS with automatic model selection. Decomposes the series into trend, multiple seasonal components, and remainder. Forecasts are generated by extrapolating each component.

> **Note:** `AutoMSTL` currently runs the exact same code path as `MSTL` (an alias — only the
> reported `model_name` differs), not a separate model-selection algorithm. When
> `seasonal_periods` is omitted, `ts_forecast_by` auto-detects a single period internally
> and uses it as the only entry — falling back to the fixed period 12 if nothing is detected.
> Passing `seasonal_periods` explicitly via `ts_detect_periods_by` is still recommended.
> (being corrected in v0.10.0, Phase 10)

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `horizon` | INTEGER | Yes | — | Number of periods to forecast |
| `seasonal_periods` | INTEGER[] | No | auto-detected (single period) or `[12]` | Array of seasonal periods (e.g., `'[7, 365]'` for weekly+yearly); see Note above when omitted |
| `confidence_level` | DOUBLE | No | 0.90 | Confidence for prediction intervals |

## Returns

| Column | Type | Description |
|--------|------|-------------|
| `group_col` | ANY | Series identifier (only for `_by` variant) |
| `<date_col>` | (same as input) | Forecast timestamp |
| `yhat` | DOUBLE | Point forecast |
| `yhat_lower` | DOUBLE | Lower prediction interval |
| `yhat_upper` | DOUBLE | Upper prediction interval |

`yhat_lower` / `yhat_upper` are currently a heuristic `point ± z·SD(history)·√h` band, not a
model-based interval and not statistically calibrated. For calibrated coverage, use conformal
prediction intervals (see `docs/api/11-conformal-prediction.md`) on top of the point forecast.
(being corrected in v0.10.0, Phase 10)

## SQL Example

```sql
-- Step 1: Detect seasonality
SELECT * FROM ts_detect_periods_by('daily_sales', product_id, date, quantity, MAP{});
-- Returns: periods = [7, 365] (weekly and yearly)

-- Step 2: Forecast with detected seasonal periods
SELECT * FROM ts_forecast_by(
    'daily_sales',
    product_id,
    date,
    quantity,
    'AutoMSTL',
    90,
    '1d',
    MAP{'seasonal_periods': '[7, 365]'}
);
```

## Best For

- Data with multiple seasonal patterns at different frequencies
- Long time series with yearly and weekly seasonality
- When you need interpretable decomposition
- Retail, energy, and traffic data with complex patterns
