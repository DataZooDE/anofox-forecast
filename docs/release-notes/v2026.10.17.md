# anofox_forecast v2026.10.17 — DuckDB 2.0 Compatibility

**anofox_forecast v2026.10.17 runs on DuckDB 2.0-dev.** It is a compatibility
release: on DuckDB v1.4.5 LTS and v1.5.6 every SQL function, signature and numeric
result is unchanged from [v2026.10.16](v2026.10.16.md). No upgrade steps are needed.

## What changed

- **DuckDB 2.0-dev support.** One source tree now builds and passes the full SQL
  suite (5591 assertions across 94 test files) on DuckDB 2.0-dev, v1.5.6 and v1.4.5
  LTS. A new compatibility header, `src/include/duckdb_compat.hpp`, routes every
  DuckDB API call and picks the right API by its shape, not by a version number.
- **Same results on every engine.** Fifteen table-function families, run 20 times on
  1,000 series with 20 threads, return identical row counts on v1.5.6 and 2.0-dev;
  AutoETS forecasts are byte-identical across both.
- **Clearer errors on 2.0.** Scalar functions are marked fallible, so an invalid
  argument on DuckDB 2.0 raises a normal error rather than an internal one.
- **Two input-reading fixes.** `ts_estimate_backtest_memory` no longer reads past
  the end of a constant input, and `ts_features_config_from_json` works on 2.0.
- **WASM builds use Rust 1.86.0**, because newer Rust emits WebAssembly features that
  DuckDB's current Emscripten toolchain rejects. Native builds are unaffected.
- **CI** gains a non-blocking DuckDB 2.0-dev job (`linux_amd64` and `wasm_eh`) that
  runs the full SQL suite.
