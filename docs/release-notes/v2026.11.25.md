# anofox_forecast v2026.11.25 — bounded AutoARIMA fits, AutoETS seasonal component

**anofox_forecast v2026.11.25 lets you bound the cost of an AutoARIMA fit and fills in the
AutoETS seasonal component in `ts_forecast_inspect_by`. It moves to the `anofox-forecast`
crate 0.22.0.** No SQL names, parameters or output columns were removed or renamed, and
results without the new parameters are unchanged.

## Highlights

- **Bounded AutoARIMA fits (#318).** A seasonal AutoARIMA search with a long period
  (m = 30 or 52 on hundreds of weekly points) can take minutes per series. Two new `params`
  keys bound one fit:
  - `max_models` caps the stepwise search. It defaults to 94, as in R, and is deterministic.
  - `time_budget_ms` returns the best model found within the budget. It is not reproducible
    across machines, and DuckDB-Wasm ignores it.

  On the weekly series from the issue, `{time_budget_ms: 2000}` finishes in 2.4 s instead of
  211 s. Both keys work on `ts_forecast_by`, `ts_forecast_agg`, `ts_forecast_exog_by`,
  `ts_cv_forecast_by` and `ts_forecast_inspect_by`.
- **AutoETS `seasonal_component` (#316).** `ts_forecast_inspect_by` returned it as `NULL` for
  seasonal AutoETS fits, and `trend_component` was a copy of `fitted_values`. Each fitted
  value now splits into a level/trend part and a seasonal part that sum, with the residuals,
  to the input series. The initial states (`initial_level`, `initial_trend`,
  `initial_seasonals`) are in `raw_json`.
- **`permutation_entropy` is deterministic (#321).** The fix shipped in v2026.10.31 and is
  live on the community registry since v2026.11.19. If you installed an older build, use
  `FORCE INSTALL anofox_forecast FROM community;`.
