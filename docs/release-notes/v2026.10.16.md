# anofox_forecast v2026.10.16 — Statistical Correctness

**anofox_forecast v2026.10.16 makes a single promise: every statistic the extension
returns is correct.** Every forecasting model, metric, data-quality score, feature,
detection algorithm, and diagnostic test in this release has been checked against a
reference implementation — R, scipy, statsmodels, or tsfresh — using checked-in
fixtures, not eyeballed. Where the old wrapper fabricated a result (prediction
intervals, fitted values, residual-splicing on NULLs, silent model fallbacks), it now
either delegates to the real computation in the Rust core or raises a clear SQL error
naming the problem.

This is a **breaking-changes release**: because every numeric output that was wrong is
now fixed, many `ts_*` function results will differ from v0.9.x on the same input, and
a handful of SQL signatures changed to make the correct behaviour expressible at all
(conformal prediction intervals, `ts_mase`, stationarity testing). See
[CHANGELOG.md's "Breaking changes in v2026.10.16"](../../CHANGELOG.md#breaking-changes-in-v0100)
for the complete, function-by-function record — this document is a release-facing
summary and upgrade guide.

## Highlights by area

- **Forecasting:** prediction intervals, fitted values, and residuals now come from
  each model's own crate implementation (`predict_with_intervals`, `fitted_values()`,
  `residuals()`) instead of a fabricated `point ± z·SD·√h` band or an SES(α=0.3)
  surrogate. `'ARIMA'`/`'SARIMA'` run a real fit given `arima_order`. Every silent
  model/parameter fallback (bad seasonal period, unrecognised model name, crate
  panic) is now a SQL error naming the problem, on every forecast surface including
  `ts_forecast_agg`. `anofox-forecast` 0.16.2 also brings R `forecast`-parity ETS,
  Theta, and AutoARIMA (R `auto.arima`'s own stepwise search and, since 0.16.2, R
  `stats::arima`-parity 95% prediction intervals too).
- **Statistics & data quality:** moments (`skewness`/`kurtosis`), entropy, and gap
  counting are now textbook/scipy/R-exact; `trend_strength`/`seasonality_strength`
  are Wang/Hyndman STL strengths from an R-faithful STL port; `ts_data_quality_summary`
  gained an `n_unassessed` column so `n_good+n_fair+n_poor+n_unassessed=n_total`
  always holds.
- **Features:** all 117 tsfresh-inspired features match tsfresh 0.21.2 (or a
  documented, intentional deviation) — including `autocorrelation_lag10`, which
  previously never reached any SQL surface at all.
- **Detection & decomposition:** peak detection is a direct `scipy.signal.find_peaks`
  port; BOCPD uses a correctly normalised Student-t predictive and is scale-invariant;
  MSTL is a real R `forecast::mstl` port that actually honours the periods you ask
  for; period estimators and seasonal-strength measures are scipy/statsmodels-faithful
  and detrend first. `ts_detect_periods`/`ts_detect_periods_by`'s default call (no
  `expected_periods`) now returns a populated row instead of an all-NULL one (`DET-01`
  gap closure, plan 18-06) — see CHANGELOG.md's `### Fixed` entry for the root cause.
- **Conformal prediction & bootstrap:** every conformal surface is paired by a
  required `date_col` instead of independently value-sorted lists (fixing a silent
  mispairing bug); asymmetric conformal hits nominal coverage instead of
  over-covering by 5-6 percentage points; the `'jackknife+'` strategy — which
  computed the identical quantile to `'split'` with no real leave-one-out refits —
  is removed.
- **Diagnostics:** `ts_adf`/`ts_kpss` match `statsmodels`/R `tseries` exactly
  (AIC-selected lags, MacKinnon finite-sample critical values, a new trend-KPSS
  implementation); `ts_stationarity`'s four-way verdict is the standard ADF+KPSS
  mapping (three of four labels were previously swapped); `ts_ljung_box` gained a
  `fitted_params` parameter matching R `Box.test(fitdf=...)` exactly.
- **No statistics in C++ or SQL.** A new audit (`make audit`, `.github/workflows/audit.yml`)
  continuously verifies that every statistical computation lives in the Rust core —
  C++ and SQL macros only marshal, group, and dispatch.
- **Docs & skills accuracy.** A permanent snippet checker (`make check-docs`) runs
  every SQL example in `docs/`, `README.md`, and the `anofox-forecast` Claude Code
  skills against the built extension; the full milestone's docs/skills sweep is
  0 FAIL / 0 STALE under it.

## Upgrading

### Conformal prediction: `date_col` is now required, output is one row per `(group, date)`

```sql
CREATE TABLE conformal_src AS
SELECT product_id, date, value AS actual, value + 1.0 AS forecast
FROM sales;

-- v2026.10.16: date_col required, one row per (group, date), paired not independently sorted
SELECT * FROM ts_conformal_by('conformal_src', product_id, date, actual, forecast, 0.1);
```

### `ts_mase`: now Hyndman-Koehler MASE, `seasonal_period` required; old relative-MAE is `ts_rmae`

```sql
-- v2026.10.16: 4-arg Hyndman-Koehler MASE (insample + seasonal_period)
SELECT ts_mase([110.0, 120.0]::DOUBLE[], [111.0, 119.0]::DOUBLE[],
               [100.0, 105.0, 95.0, 102.0]::DOUBLE[], 1) AS mase;

-- Old 3-arg relative-MAE behaviour now lives in ts_rmae
SELECT ts_rmae([110.0, 120.0]::DOUBLE[], [111.0, 119.0]::DOUBLE[], [109.0, 122.0]::DOUBLE[]) AS rmae;
```

### Stationarity testing: `regression := 'c' | 'ct'`, four-way verdict corrected

```sql
SELECT ts_stationarity(
    (SELECT LIST(value ORDER BY date) FROM sales WHERE product_id = 1),
    'c'
);
```

### `ts_data_quality_summary`: new `n_unassessed` column

```sql
SELECT n_total, n_good, n_fair, n_poor, n_unassessed, avg_score
FROM ts_data_quality_summary('sales', product_id, date, value, 10);
```

### Deprecated metric `_by` macros: `source` must be a subquery

```sql
SELECT * FROM ts_mae_by(
    (SELECT product_id, date AS d, value AS actual, value + 1.0 AS forecast FROM sales),
    'd', 'actual', 'forecast'
);
```

### `ts_diff_by`: `diff_order` is now true d-th order differencing

```sql
-- True second difference (numpy diff(n=2)) -- the v2026.10.16 default meaning
SELECT * FROM ts_diff_by('sales', product_id, date, value, 2);

-- Old pre-v2026.10.16 lag-2 reading (y[t] - y[t-2]): use seasonal_lag instead
SELECT * FROM ts_diff_by('sales', product_id, date, value, 1, seasonal_lag := 2);
```

## Known limitations

- **TBATS / AutoTBATS interval width.** The interval formula is verified (Monte Carlo
  self-consistency and 97.6% coverage). On some series, though, the width differs from
  `statsforecast` by up to ~6x because the crate optimiser lacks the `D = F - g·w'`
  admissibility check and can settle on near-unstable parameters. Upstream follow-up.
- **ETS(M,A,M) parameters.** The corrected multiplicative-error likelihood matches R `ets` to
  <1e-12 at R's own parameters. On AirPassengers the crate's optimiser finds a different and
  slightly better local optimum (alpha ≈ 0.79, gamma ≈ 0.21, log-likelihood -681.11 versus R's
  -682.40), so its smoothing parameters differ from R's (alpha ≈ 0.40, gamma ≈ 0.40).
- **No DuckDB LTS v1.4.5 macOS binaries in this release.** GitHub's macos-26 runner image
  (2026-10-13) breaks linking on the LTS v1.4.5 toolchain, which fails to link DuckDB core
  itself. Our code is not the cause. LTS macOS builds are excluded until the image or
  DuckDB's extension-ci-tools is fixed. DuckDB v1.5.6 binaries for macOS (arm64 and x86_64) ship
  as usual, and LTS v1.4.5 ships for Linux and WASM.
