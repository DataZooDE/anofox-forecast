# anofox_forecast v2026.10.31 — DuckDB 2.0 features, contract outputs, faster stats

**anofox_forecast v2026.10.31 adopts DuckDB 2.0 features while staying fully usable on
DuckDB v1.5.6.** No SQL names, parameters or output columns were removed or renamed; all
additions are additive. One default changed: changepoint detection now deseasonalizes clearly
seasonal series first (`'deseasonalize': 'false'` restores the previous output).

## Highlights

- **DuckDB 2.0.** Rolling-origin forecasts as window functions (#297), exportable and mergeable
  aggregate states (#298), correct ROLLUP / GROUPING SETS / CUBE (#299), `params` as STRUCT /
  MAP / VARIANT / `{}` (#300), and guides for triggers (#302) and SQL variables (#303).
- **anofox contract outputs.** `anofox_contract_version()` and tagged producers (#279), long-form
  companions (#282), `ts_metrics_by` (#281), contract prediction columns (#280),
  `ts_detect_changepoints_events_by` (#283), and the Durbin-Watson `p_value` (#284).
- **Faster.** `ts_stats` is sub-quadratic: 160k rows take 0.9 s instead of 44 s (#304).
  `ts_aggregate_hierarchy` is about 10× faster (#305).
- **Fixes.** `ts_*_agg` crashed as window functions (#294). DuckDB-Wasm returned wrong
  forecast-fill results (#289). The UNION ALL / row-order bugs in the `_by` macros are fixed
  (#285). The seasonality classification is consistent with `ts_stats_by` (#286). The weekly
  troughs are no longer flagged as changepoints (#287). get.erpl.io WASM signing is fixed (#272).
- **Forecasting crate 0.19.0.** AutoETS no longer extrapolates one-off spikes (#259), and there is a
  conditioning-aware ridge backend (#258).
