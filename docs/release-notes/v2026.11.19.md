# anofox_forecast v2026.11.19 — forecasting crate 0.21.0, inspect params validated

**anofox_forecast v2026.11.19 moves to the `anofox-forecast` crate 0.21.0 and makes the
explainability macros validate their parameters.** No SQL names, parameters or output columns
were removed or renamed.

## Highlights

- **AutoETS fits seasonal models on shorter series.** Seasonal candidates are considered from
  two full cycles instead of three (24 instead of 36 monthly observations), and model choice no
  longer depends on the units of the data. Forecasts change for short seasonal series, which
  used to get a flat non-seasonal model, and can change for small-valued series.
- **Faster seasonal AutoARIMA.** About 1.6× faster on monthly data, with identical results.
  Long seasonal periods (weekly data with m = 30 or 52) are still expensive (#318). Pass an
  explicit `seasonal_period`, or use AutoETS, for such series.
- **`ts_forecast_inspect_by` / `ts_forecast_explain_by` validate `params` (#315).** Unknown keys
  and `model` with a non-ETS method now error, as in `ts_forecast_by`, instead of silently
  inspecting a different fit.
- **No `wasm_threads` binary on DuckDB v2.0.0.** The upstream build tooling now links
  `wasm_threads` with shared memory, which Rust's prebuilt WebAssembly std does not support.
  Use `wasm_eh` in the browser. The v1.5.6 line is unchanged.
