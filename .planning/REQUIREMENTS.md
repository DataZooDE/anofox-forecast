# Requirements: anofox-forecast — v0.10.0 Statistical Correctness

**Defined:** 2026-10-08
**Core Value:** Every statistic the extension returns is correct — verified against R / scipy / statsmodels / tsfresh reference values — and is computed in the Rust crates; C++ and SQL only marshal, group, and dispatch.

Source: `.planning/research/STAT-AUDIT-2026-10-08.md` (finding IDs in brackets).
Scope decision (user, 2026-10-08): **fix all** audit findings. Upstream anofox-forecast fixes go on a branch + PR in `~/projects/rust/anofox-forecast`; the user reviews, merges and publishes; the extension may use an interim `[patch]` git/path dependency on the fix branch only.

**Universal DoD for every requirement:** a test asserting *values* (not lengths) against a checked-in reference fixture generated by a checked-in R/Python script (or a closed-form expected value); `cargo test` + `cargo fmt --check` + `cargo clippy` green; affected SQL exercised against the built extension; docs/skill text matches the new behaviour.

## v1 Requirements

### Test Foundation

- [x] **TEST-01**: A reference-fixture harness exists: `validation/reference/` generator scripts (R + Python) produce versioned fixture files (JSON/CSV) that Rust tests load; a README documents regeneration and tolerances.
- [x] **TEST-02**: The existing length-only tests for every module touched in this milestone are upgraded to value assertions.
- [x] **TEST-03**: A SQL-level regression suite (`test/sql/correctness/*.test`) pins the corrected results of each user-facing function fixed in this milestone.

### Dependencies

- [x] **DEP-01**: anofox-regression bumped `=0.5.3` → `=0.5.15`; multi-scale exogenous OLS matches numpy `lstsq` (fixes coefficient scrambling + O(n²) memory) [H].
- [x] **DEP-02**: anofox-forecast bumped to ≥0.15.10 (MFLES runaway, panel NaN guards, Laplace leaf fixes) [H].
- [x] **DEP-03**: fdars-core bumped 0.3 → 0.47 with features `["parallel"]` (no `linalg`, removing the duplicate anofox-regression 0.4.0); native + WASM builds compile [H].
- [x] **DEP-04**: Documented/CI MSRV matches what the dependency tree actually requires [H toolchain].

### Forecast Wrapper (crates/anofox-fcst-core/src/forecast.rs, FFI)

- [x] **FCST-01**: Prediction intervals for every model come from the crate model (`predict_with_intervals(h, level)`); `calculate_confidence_intervals` is deleted; models with no native intervals return NULL bounds [A1, A3-Laplace].
- [x] **FCST-02**: Confidence level → quantile uses the exact normal inverse CDF wherever a z-value is needed (no step table) [A2].
- [x] **FCST-03**: Fitted values, residuals and MSE come from the crate model (`fitted_values()`/`residuals()`); `calculate_fitted_values` is deleted; MSE excludes interpolated points [A3].
- [x] **FCST-04**: Model "ARIMA" is a real crate ARIMA fit (user-specified or default order), never the fixed-coefficient AR(1) [A4].
- [x] **FCST-05**: Exogenous forecasting routes through the crate's exog support (AutoARIMA search actually runs; Optimized/Dynamic Theta stay themselves; ETS/GARCH/Kalman options honoured); a regressor constant in history gets a 0 (not NaN) effect and a warning-free finite forecast [A5, A6, A15].
- [x] **FCST-06**: Silent fallbacks become errors or are explicitly reported: AutoETS crate error, "ETS" without spec, AutoMFLES/AutoMSTL aliases, default period 12 / period 2, unknown kalman_model, panel Croston variant, invalid UTF-8 model name, unparsable seasonal periods; the returned model name always identifies the model that actually ran [A7–A12].
- [x] **FCST-07**: Ensemble members built by `build_forecaster` use the same defaults as the standalone model; "ETS" means the same model everywhere [A8, A14].
- [x] **FCST-08**: Series input handling is explicit and documented: all-NULL series → error; valid NaN treated as missing; regressor NULLs handled via validity [A13].
- [x] **FCST-09**: AirPassengers + simulated-series fixtures: point forecasts and 95% intervals for Naive, SNaive, RWD, SES, Holt, HW, AutoETS, AutoARIMA, Theta, Croston are within documented tolerance of R `forecast`, and Monte-Carlo interval coverage is within ±3pp of nominal for the local-level case [A1, H].

### Wrapper Bug Fixes

- [x] **WRAP-01**: fdars calls in detrending.rs and seasonality.rs pass the series correctly; `ts_detrend`, `ts_detrend_by`, `ts_decompose_seasonal`, `classify_seasonality`, amplitude-modulation return non-trivial results matching numpy `polyfit` / reference; `'quadratic'` maps to polynomial degree 2 or errors [B1–B3].
- [x] **WRAP-02**: `ts_data_quality_by` passes dates, frequency and n_short; gap/temporal scores reflect real gaps; `find_mode` ties are deterministic [E6, E7].
- [x] **WRAP-03**: `detect_frequency` is deterministic on ties and its unit (µs) is documented correctly; monthly/quarterly/yearly gap fill preserves month-end alignment [G23, G24].

### Statistics Out of C++/SQL (Marshalling)

- [x] **RUST-01**: All list-taking scalar functions read inputs via `ToUnifiedFormat` (constant/dictionary list arguments give correct per-row results) [D2].
- [x] **RUST-02**: List NULLs are passed to Rust as validity; Rust owns the policy: paired metrics/conformal use pairwise-complete observations; single-series diagnostics reject or explicitly handle interior NULLs instead of splicing; one shared C++ helper replaces the ~10 copies of `ExtractListAsDouble` [D1].
- [x] **RUST-03**: `ts_diff_by` computes d-th order differences via Rust `diff` (optionally a separate seasonal-lag parameter) [D3].
- [x] **RUST-04**: `ts_conformal_by`, `ts_conformal_apply_by`, `ts_interval_width_by`, `ts_conformal_calibrate` preserve horizon order (date/step column) and pairing; residuals and empirical coverage are computed in Rust; per-group calibration supported [D4–D6].
- [x] **RUST-05**: `ts_fill_nulls_mean_by` uses the Rust implementation [D7].
- [x] **RUST-06**: `ts_backtest_native` either computes metrics per group via the Rust metric functions (unknown metric → error, missing bounds → NULL) or is removed together with stale `ts_backtest_auto_by` references; error sign convention is consistent across surfaces [D8, D16].
- [x] **RUST-07**: Hierarchy aggregation keeps SQL `SUM` NULL semantics (all-NULL → NULL, no NULL→0 imputation) [D9].
- [x] **RUST-08**: `ts_forecast_agg` uses Rust frequency detection with calendar-aware month/year stepping; `ts_forecast_agg` and `ts_features_agg` pass validity instead of splicing NULL rows [D10, D11].
- [x] **RUST-09**: Per-step conformal validates that the residual count is a multiple of horizon; drop_constant uses the Rust tolerance; `ts_forecast_exog_by` future-date generation is calendar-correct; dead `ts_filter.cpp`/`ts_imputation.cpp` scalar bodies removed or registered [D12–D15].
- [x] **RUST-10**: An audit script (grep-based, run in CI or as a test) confirms no statistical arithmetic remains in `src/**/*.cpp` or macro SQL beyond documented marshalling.

### Core Statistics (stats.rs, quality.rs, metrics.rs)

- [x] **STAT-01**: `ts_stats` skewness/kurtosis equal scipy `skew(bias=False)` / `kurtosis(bias=False)`; bimodality coefficient uses the SAS small-sample formula [E1, E2].
- [x] **STAT-02**: Trend and seasonal strength use the Wang/Hyndman STL definitions (F_T, F_S) matching R `feasts`/manual STL reference; EDA skill thresholds updated [E3].
- [x] **STAT-03**: Entropy and n_gaps semantics are correct and documented (missing periods vs gap intervals both available or clearly named) [E4, E5].
- [x] **STAT-04**: `behavioral_score` design reviewed; scoring no longer penalises predictable smooth series without rationale, documented [E8].
- [x] **STAT-05**: MAPE zero-actual policy explicit (NULL or documented exclusion with count) [E9].
- [x] **STAT-06**: MASE is Hyndman-Koehler (scaled by in-sample seasonal-naive MAE with a seasonal-period parameter); the old relative-MAE behaviour stays available as `rmae` only [E10].

### Features (features.rs, tsfresh parity)

- [x] **FEAT-01**: PACF lags 1–N via Durbin-Levinson match statsmodels/tsfresh [F1].
- [x] **FEAT-02**: mean_second_derivative_central, last_location_of_max/min, time_reversal_asymmetry, agg_linear_trend rvalue, skewness/kurtosis match tsfresh exactly [F2–F4, F7, F8].
- [x] **FEAT-03**: fft_coefficient (unnormalised, O(n log n)) and spectral centroid/variance (one-sided, tsfresh fft_aggregated) match tsfresh [F5, F6].
- [x] **FEAT-04**: sample_entropy, binned_entropy, benford_correlation, permutation_entropy, lempel_ziv_complexity, number_peaks match tsfresh (or are renamed with documented definitions where deliberately different) [F9–F11].
- [x] **FEAT-05**: A tsfresh-generated fixture covers all 117 features on ≥4 series; every feature matches within tolerance or is listed as an intentional, documented deviation.

### Detection & Decomposition

- [x] **DET-01**: Peak detection follows scipy `find_peaks` semantics (indices, plateaus, prominence) and matches scipy on fixtures [G1].
- [x] **DET-02**: BOCPD implements Adams & MacKay correctly (normalised Student-t predictive, correct Normal-Gamma update, truncation keeps mass, changepoint rule detects a 3σ step and stays quiet on stationary noise) [G3–G6].
- [x] **DET-03**: PELT penalty is scale-invariant (variance-normalised cost or BIC-style penalty with σ²); normal and L1 costs correct (median for L1); pruning implemented [G7, G8].
- [x] **DET-04**: MSTL processes periods shortest-first with STL (Loess) components matching R `forecast::mstl`/statsmodels within tolerance; even-window averages correct [G9–G11].
- [x] **DET-05**: Period detection is robust: FFT detrends before the periodogram and handles odd n; ACF period allows lag 2 and requires significance; regression-period defaults include integer candidates; Lomb-Scargle validates inputs [G17, G18, G20, G21].
- [x] **DET-06**: Seasonal-strength variants detrend before measuring; wavelet strength is fixed (noise ≈ 0) or removed; trend-strength doc matches implementation [G19, G22].
- [x] **DET-07**: is_constant uses a scale-relative tolerance; edge-NULL interpolation behaviour documented [G25, G26].

### Conformal & Bootstrap

- [x] **CONF-01**: Bootstrap paths add residuals with the correct sign; skewed-residual fixture gives correct-side intervals [G2].
- [x] **CONF-02**: Split conformal returns infinite/NULL width (or errors) when ⌈(n+1)(1−α)⌉ > n; α ∉ (0,1) rejected; NaN residuals filtered [G12, G16].
- [x] **CONF-03**: Asymmetric conformal uses α/2 and 1−α/2 quantiles of signed residuals; simulated coverage within ±2pp of nominal [G13].
- [x] **CONF-04**: Adaptive conformal uses normalised scores |r|/d at calibration and d-scaling at prediction, independent of batch composition [G14].
- [x] **CONF-05**: "JackknifePlus" either implements jackknife+ or is renamed/removed [G15].

### Diagnostics (upstream anofox-forecast + core validation.rs)

- [x] **DIAG-01**: ADF is augmented (lagged differences in the regression), supports constant and constant+trend, selects lags by AIC/BIC, and reports MacKinnon p-values; statistic matches `urca::ur.df`/statsmodels `adfuller` on fixtures; size ≈ 5% on a unit-root simulation [C1, C2, H1].
- [x] **DIAG-02**: KPSS p-values are bounded to [0.01, 0.10] with interpolation inside the table (matches `tseries::kpss.test`) [C3, H2].
- [x] **DIAG-03**: `classify_stationarity` uses the standard ADF/KPSS four-way mapping, can produce trend-stationary (trend variants), and handles constant series explicitly [C4].
- [x] **DIAG-04**: Ljung-Box accepts `fitted_params` (df = lags − p − q) from SQL [C5].
- [x] **DIAG-05**: docs/api/10-diagnostics.md claims match verified behaviour [C6].

### Upstream Models (anofox-forecast branch + PR)

- [x] **UPST-01**: AutoARIMA selects d by KPSS and D by a seasonal test (OCSB or seasonal-strength), compares candidates by AICc on a common likelihood basis; random-walk and stationary-AR selection frequencies are close to R `auto.arima` in simulation [H3].
- [x] **UPST-02**: ETS likelihood is correct for multiplicative error (Σ ln|ŷ|), includes all observations, applies usual parameter constraints; AutoETS AICc comparisons valid; AirPassengers parameters/forecasts near R `ets` [H4].
- [x] **UPST-03**: ETS prediction intervals use Hyndman et al. analytic variances (class 1/2) or simulation for class 3; coverage verified [H5].
- [x] **UPST-04**: Theta (STM) estimates α (SES optimisation) and its intervals follow the standard formula; random-walk bias removed vs R `thetaf` [H6].
- [x] **UPST-05**: TBATS/MSTL/GARCH interval gaps from upstream's own validation report are fixed or the affected models return NULL intervals with documentation [H7].
- [x] **UPST-06**: Upstream changes land as PR(s) in `~/projects/rust/anofox-forecast` with tests + CHANGELOG; the extension consumes them (interim `[patch]`, final released version after user publishes).
