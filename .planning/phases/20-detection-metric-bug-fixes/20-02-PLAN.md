## Planner-verified facts (2026-10-23, build/release at 9d11361, DuckDB v2.0.0)

- #285 setup: `CREATE TABLE s AS SELECT id, (TIMESTAMP '2024-01-01' + INTERVAL (i) DAY) AS ds, base + 0.3 * i + 5 * sin(2 * pi() * i / 7) + CASE WHEN id = 'B' AND i >= 50 THEN 15 ELSE 0 END + 1.6 * cos(i * 0.9) + 0.7 * sin(i * 1.7 + base) AS y FROM (VALUES ('A', 20.0), ('B', 40.0), ('C', 60.0)) t(id, base), range(84) r(i); CREATE TABLE f AS SELECT id, ds, y, y + 1 AS yhat FROM s WHERE ds >= TIMESTAMP '2024-03-11';`
- On this build BOTH the literal cut-off and the scalar-subquery cut-off shapes return NULL for A/B/C (also with `SET threads = 1`); the issue body saw only the subquery shape fail. Which branch finishes first is plan- and version-dependent, so tests must cover both shapes plus reversed and shuffled.
- `ts_mae_by((SELECT id, ds, y, y+1 AS yhat FROM s WHERE ds < TIMESTAMP '2024-02-01' UNION ALL SELECT id, ds, y, y+3 FROM s WHERE ds >= (SELECT min(ds) FROM f)), 'ds', 'y', 'yhat')` returns exactly 1.0 per group: only the first branch reached the computation (the all-rows MAE is (31*1 + 14*3)/45).
- Mechanism (DuckDB v2.0.0 source in the duckdb/ submodule): a UNION ALL below an operator creates two pipelines that share the operator's global state (src/parallel/pipeline.cpp ResetSinkAndOperators creates op_state only once), and PipelineExecutor calls FinalExecute (our in_out_function_final) at the end of EACH pipeline (src/parallel/pipeline_executor.cpp ~line 169-198). Our natives' finalize_claimed/threads_collecting barrier only waits for threads that already called InOut, so the first finishing pipeline claims finalize and emits results on partial data; later rows are collected and never emitted.
- Fix proven by probe: `SELECT * FROM (WITH src AS MATERIALIZED (<the #285 subquery-cutoff UNION ALL>) SELECT * FROM _ts_mase_native((SELECT * FROM src), 'ds', 'y', 'yhat', 7))` returns A 0.4764952155298452, B 0.26551450050730596, C 0.4759518449064799 (a materialized CTE scan is ONE pipeline). Same values as the issue's sorted variant.
- A table macro cannot write `FROM source` when `source` is a subquery argument (Catalog Error: Table with name source does not exist); parameters substitute only in expression positions such as a table-function argument. Hence `_ts_passthrough(source)`: a streaming identity in-out function (no in_out_function_final, so it is correct under any number of pipelines) that turns the argument into a relation a MATERIALIZED CTE can read.
- A pipeline can still run with several executors: a thread that receives no chunk can reach FinalExecute before another thread's first InOut registered it (threads_collecting still 0), finalizing on partial data. `TableInOutGlobalState::MaxThreads` forwards the table function global state's MaxThreads() to the pipeline (duckdb src/execution/operator/projection/physical_tableinout_function.cpp:24-29; pipeline.cpp:145), so returning 1 leaves exactly one executor and one FinalExecute. Every natives' MaxThreads() currently returns 999999. The heavy work already runs single-threaded in finalize, so this costs only intake parallelism.
- The metric natives in src/table_functions/ts_metrics_native.cpp: _ts_metrics_native (macros ts_mae_by, ts_mse_by, ts_rmse_by, ts_mape_by, ts_smape_by, ts_r2_by, ts_bias_by), _ts_mase_native (ts_mase_by), _ts_rmae_native (ts_rmae_by), _ts_coverage_native (ts_coverage_by), _ts_quantile_loss_native (ts_quantile_loss_by); macro bodies at src/macros/ts_macros.cpp ~2429-2575, each `SELECT * FROM _ts_..._native(source, ...)`.
- R MASE reference: validation/reference/r/gen_mase_reference.R writes r_mase/accuracy_mase.json (cases keyed by name, fields include mase_accuracy and mase_manual), consumed by crates/anofox-fcst-core/tests/metrics_reference.rs; `Rscript validation/reference/r/gen_mase_reference.R` works locally.
- `make audit` (scripts/audit_no_stats_in_cpp.py) flags math calls, accumulators and std::sort-family calls in src/**; a new hit must be allow-listed with a marshalling justification in scripts/audit_allowlist.txt or avoided. The passthrough and guard code contain none.
