### Evidence for the Task 2 decision (SQL prototype on the built extension; the transform was emulated with ts_mstl_decomposition_by(MAP{'seasonal_periods': '[7]'}), i.e. the same Rust mstl_fit the implementation will call)

#287 panel, hazard_lambda 250. "Rule H" = today's MAP-run-length-drop flags; "p>=0.5" = flag where changepoint_probability >= 0.5.

| Input to BOCPD | Rule H flags | p >= 0.5 flags | B's p at 2024-02-20 |
|---|---|---|---|
| raw series (today's default) | A,C: 01-22, 01-29, 02-05, 02-12, 02-19, 02-26; B: 01-29, 02-20 | A: 01-01; B: 01-01, 02-20; C: 01-01 | 0.52 |
| (a) y minus STL seasonal, trend kept (CONTEXT #287 decision 1 as written) | A: 12 dates, B: 01-19, 01-22, 01-26, 02-10, 02-17, 02-20, C: 10 dates | A: 01-01; B: 01-01; C: 01-01 (shift missed) | 0.175 |
| (b) y minus STL seasonal, then minus an OLS line (level shift kept as a step) | A: none; B: 01-16, 01-23, 01-30, 02-20, 03-05, 03-12, 03-19; C: none | A: 01-01; B: 01-01, 02-20; C: 01-01 | 0.663 |
| (c) STL remainder only (seasonal and STL trend removed) | A: none; B: 02-13, 02-16, 02-23 (shift smeared, 02-20 missed); C: none | not measured | - |

- Why (a) fails: BOCPD's Normal-Gamma model has a piecewise-constant mean; a kept linear trend (0.3/day, about 50 robust-sigma over 84 days once the weekly cycle no longer inflates the noise scale) forces a run reset every few days.
- The first row: `changepoint_probability` at t = 0 is P(r_0 = 1) = 1 - 1/hazard_lambda for every series (0.996 at 250, 0.98 at 50), independent of the data. It is the "p = 0.996" in #287 and ROADMAP criterion 4. Rule H never flags t = 0 (bocpd_trace requires a run start >= 1).
- Only option (b) with the first row excluded meets "none on A/C, B on 2024-02-20" (REQUIREMENTS BUG-05), and only when a threshold is set; with Rule H, (b) still leaves weekly-spaced flags on B.
