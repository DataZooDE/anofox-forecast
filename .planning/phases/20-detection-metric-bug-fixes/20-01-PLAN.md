<objective>
Fix BUG-04 (#286): `ts_classify_seasonality_by` / `ts_classify_seasonality_agg` / scalar `ts_classify_seasonality` stop calling a strong weekly series non_seasonal. Per locked CONTEXT #286 decision 1 (one shared Rust implementation), `classify_seasonality` takes its `seasonal_strength` from the SAME function `ts_stats_by` uses (`crate::stats::stl_strengths`, Hyndman `max(0, 1 - Var(R)/Var(S+R))` on the R-matching STL decomposition) and the divergent fdars raw-series strength is removed from the decision. Per CONTEXT #286 decision 2, `is_seasonal` keeps its 0.3 threshold, applied to the corrected strength. Per CONTEXT #286 decision 3, the strength is checked against an R tsfeatures reference.

Purpose: two functions in the same extension disagree about the same series (0.156 vs 0.966); the visualization harness (#286) cannot trust either.
Output: corrected Rust classification, consistent modulation gate, R fixture case, value pins, docs/CHANGELOG.
</objective>
