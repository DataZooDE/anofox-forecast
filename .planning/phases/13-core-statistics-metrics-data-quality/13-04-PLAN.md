<objective>
Make the accuracy metrics honest: `ts_mase` becomes Hyndman-Koehler MASE scaled by the in-sample
seasonal-naive MAE with a seasonal-period parameter, the old relative-MAE behaviour survives only as
`ts_rmae` (D-08, STAT-06), and MAPE with a zero actual returns NULL (D-07, STAT-05) — on the scalar and the
`_by` table surfaces. Then close the phase: phase-wide doc/skill/CHANGELOG sweep, deferred items, full DoD.

Purpose: ROADMAP Phase 13 success criterion 3, plus the phase-level guarantee that every doc claim made in
Phase 13 runs and is true.

Decision-conflict resolution (recorded for the user; see also the SUMMARY): D-08 writes the new signature as
`ts_mase(actual, forecast, insample, seasonal_period := 1)` AND requires the old `(actual, forecast, baseline)`
form to error. Both forms are three DOUBLE lists, so a defaulted seasonal_period would silently reinterpret an
old call's baseline as an in-sample series — exactly the silent-wrong-number failure this milestone removes.
Resolution: the scalar is a C++ overload set — `ts_mase(LIST, LIST, LIST, BIGINT)` computes HK MASE and the
3-list overload raises the removal error naming ts_rmae; seasonal_period is therefore a required 4th positional
argument (DuckDB scalar functions do not take `:=` named arguments). The `_by` table macro CAN keep the default:
`ts_mase_by(..., seasonal_period := 1)`, because an old call's 5th argument is a column name (VARCHAR) and is
detected and rejected by type.

Output: HK MASE + MAPE NULL in core, r_mase fixture, FFI/scalar/table/macro wiring, migrated tests, docs,
examples, skills, CHANGELOG, deferred-items.md.
