<objective>
Finish D-12 on every remaining forecast surface. `ts_forecast_exog_by` builds future dates with
`generate_series(last_date + interval, last_date + (len * EXTRACT(EPOCH FROM interval) || ' seconds')::INTERVAL, interval)`
— a 30-day-month / 365.25-day-year epoch bound against a calendar step, so the row count can drift from
len(point) and misalign the zipped UNNEST (RUST-09, ROADMAP criterion 4 exog half). Replace it with a
Rust-backed `_ts_future_dates` scalar (D-12 rule from plan 12-05), and move the four remaining C++
calendar steppers (ensemble, panel ×2, var, native) to the same Rust rule so no forecast surface does
month arithmetic in C++ any more.

Execution environment: worktrees disabled — branch `fix/statistical-correctness`, main tree; reuse
`build/release`; ONE full build in Task 3; Tasks 1-2 use compile-only ninja object checks.
`ts_forecast_exog_by` needs the json extension (to_json/json_extract) — natively it can only be proven
through the CLI example (`./build/release/duckdb -unsigned` loads json from the local extension cache);
`_ts_future_dates` itself is proven by a non-gated unittest.
</objective>
