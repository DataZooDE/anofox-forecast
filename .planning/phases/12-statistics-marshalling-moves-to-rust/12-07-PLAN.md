<objective>
Move the last SQL-macro statistics into Rust (RUST-03, RUST-05, RUST-09 drop_constant/dead files):
`ts_diff_by` becomes d-th order differencing via the Rust `diff` with a new `seasonal_lag` parameter
(D-05/D-06), `ts_fill_nulls_mean_by` uses Rust `fill_nulls_mean`, `ts_drop_constant_by` uses Rust
`is_constant` (D-09), and the dead ts_filter.cpp / ts_imputation.cpp go away (D-09). ROADMAP criteria 2
and 5 (second half).

Decisions recorded:
- ts_diff_by NULL policy (orchestrator): SQL semantics — a difference involving a NULL/NaN input is NULL;
  no error. This is the row-wise transform exception to D-03.
- seasonal_lag composes with diff_order like R's diff(x, lag = k, differences = d); default 1 = numpy diff(n=d).
- drop_constant uses Rust is_constant in full: groups with fewer than two non-NULL values (incl.
  all-NULL groups, previously KEPT by the SQL MIN/MAX rule) are now dropped — documented breaking change.
- fill_nulls_mean treats NaN as missing (Phase 10 NaN = NULL convention); previously a NaN poisoned the
  SQL AVG.
- The macros keep their current signatures and output columns (diff: group, date, diff_value; fill: all
  source columns + filled_value; drop_constant: all source columns), so ts_type_preservation.test and
  ts_table_macro_aliases.test keep passing unchanged.
