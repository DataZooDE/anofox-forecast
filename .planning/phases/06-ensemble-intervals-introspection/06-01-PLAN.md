<objective>
Wire the INSP-01 ensemble introspection surface end-to-end as a tracer: one thin path (explicit-member Mean introspection for a 2+ member ensemble) proven core→FFI→C++→macro→example, then both introspection functions (explicit-member + AutoEnsemble) fully wired in the same delivery.

This implements INSP-01: SQL users can inspect which member models an ensemble selected and their combination weights, per series. Two dedicated `_by` functions (per RESEARCH two-function decision):
- `ts_ensemble_inspect_by` — explicit-member ensemble: full weights for all six combination methods (via `Ensemble::weights()`).
- `ts_auto_ensemble_inspect_by` — AutoEnsemble: selected members + in-sample MSE score + rank; weight = 1/k for Mean only, NULL otherwise (crate 0.15.3 exposes no inner-ensemble weight accessor for WeightedMSE/InverseAIC/Stacking/HorizonAdaptive — documented upstream limitation).

Purpose: expose the crate's `Ensemble::weights()` and `AutoEnsemble::all_scores()` accessors that Phase 5 left reachable-but-unexposed, so users can validate that a chosen combination method behaved as expected.
Output: 2 Rust core functions, 1 FFI struct + 2 FFI exports + 1 free fn, 1 new C++ .cpp (2 ScalarFunctions) + header + registration + CMakeLists entry, 2 SQL macros, 1 verified tracer example.
</objective>
