<decisions>
## Implementation Decisions

### Delivery
- **D-01:** One focused PR per area, each on its own branch created from upstream `origin/main` (currently c57e4fa, which contains 0.15.10 + merged #218): (a) `fix/adf-kpss-correctness`, (b) `fix/auto-arima-order-selection`, (c) `fix/ets-likelihood-intervals`, (d) `fix/theta-alpha-intervals`, (e) `fix/tbats-mstl-garch-intervals`. Areas must be independently mergeable (no cross-branch dependencies; if (c) and (d) share helpers, duplicate minimally or sequence and note it).
- **D-01a:** (2026-10-09, user) upstream origin/main is v0.15.9; the released v0.15.10 (1ae5cfc, tag v0.15.10) was never merged to main. Fix branches are created from 1ae5cfc (option-b), and a sync PR perf/v1.0-validation-hardening → main is opened so fix-PR diffs show only their own changes once the user merges it. Plan 11-08 (SES/Holt/HW/SeasonalES intervals) stays in scope.
- **D-02:** Each PR adds a CHANGELOG entry under a new **0.16.0** (unreleased) section describing every numerical change; bump `Cargo.toml` version to 0.16.0 only in the last-merged PR or leave version bump to the user (do NOT `cargo publish`). Pushing branches to origin and opening PRs with `gh pr create` is authorised by the user ("Branch + PR, you release").
- **D-03:** Evidence lives in the crate: checked-in R reference fixtures (generated by checked-in R scripts under the crate's `validation/`, packages: forecast, tseries, urca) plus Rust tests asserting values, and Monte-Carlo tests (size of ADF at 5% on IMA(1,1), AutoARIMA selection frequencies on random walk / AR(0.7), ETS interval coverage). Heavy simulations may be `#[ignore]`d with a documented command, but a reduced deterministic version must run in normal `cargo test`.

### Diagnostics
- **D-04:** ADF: genuinely augmented regression (Δy on y₋₁, deterministic terms, lagged Δy); regression types constant ("c"), constant+trend ("ct"), none ("n"); lag selection by AIC/BIC (and t-stat/fixed); MacKinnon (2010) response-surface p-values (approximate asymptotic distribution as in statsmodels `mackinnonp`). Keep the existing public `adf_test` signature working (defaults = constant, AIC) and add an options-taking variant. Statistic must match statsmodels `adfuller` / `urca::ur.df` on fixtures.
- **D-05:** KPSS: statistic unchanged (already matches tseries); p-value by interpolation within the table, bounded to [0.01, 0.10] exactly like `tseries::kpss.test`.

### AutoARIMA
- **D-06:** Follow Hyndman–Khandakar as in R `forecast::auto.arima`: d by repeated KPSS (α=0.05), D by a seasonal test (OCSB or seasonal-strength, as R default `seas`), candidates ranked by AICc computed on a common likelihood basis (same effective sample / exact or CSS-ML), stepwise search with R's default bounds. Target: random walk → (0,1,0)-class ≈70%, AR(0.7) → d≥1 ≈19% in simulation.

### ETS
- **D-07:** Multiplicative-error likelihood uses Σ ln|ŷ| (not Σ ln|y|) and includes all observations (no skipping the first m for seasonal models); "usual" parameter constraints (0<β<α, 0<γ<1−α, φ bounds as R); AutoETS candidate set = R `ets` defaults (excluding the unstable combinations R excludes); AICc comparisons valid across A/M error. Target: AirPassengers MAM α/γ near R (≈0.40).
- **D-08:** ETS intervals: Hyndman et al. (2008) analytic variances for class 1/2 models; simulation-based for class 3; Monte-Carlo coverage verified.

### Theta & other intervals
- **D-09:** Theta (STM): estimate α by SES optimisation as `forecast::thetaf` does; intervals by the thetaf formula; removes the random-walk bias.
- **D-10:** TBATS/MSTL/GARCH: fix intervals to match statsforecast/arch within the upstream validation tolerance if tractable within this phase; otherwise these models return no intervals (`predict_with_intervals` → point only, so the extension shows NULL bounds) with documentation. Never ship knowingly miscalibrated intervals.

### Claude's Discretion
- Internal module structure, numerical optimiser choices, test organisation, PR descriptions.
