<objective>
Replace ts_stats' ad-hoc trend strength (|r| of a linear fit) and seasonality strength (max |ACF| at
lags 2/4/7/12) with the Wang/Hyndman STL definitions F_T and F_S (D-02, STAT-02), computed from an
R-faithful STL ported into core, with forecast::mstl semantics for several periods, R's supsmu trend for
non-seasonal series, a seasonal_period parameter with auto-detection, NULL seasonal strength when no
period is usable, and updated EDA thresholds.

Purpose: ROADMAP Phase 13 success criterion 2 (strengths + EDA thresholds). Also closes the STATE.md
concern "validate the crate STL vs R stats::stl in Phase 13": the crate's
`anofox_forecast::seasonality::stl::STL` (0.15.10) is NOT R-faithful — it uses a degree-0 kernel
smoother with truncated symmetric windows, no cycle-subseries end extension and no jumps, so it cannot
match stats::stl. Per D-02 ("prefer the crate's STL if correct vs R stats::stl, else core") the STL is
ported into core here; Phase 15 DET-04 can reuse `stl.rs`.

Reference choice (D-02 names feasts, which is not installed): R `tsfeatures::stl_features` 1.1.1 —
Hyndman's own implementation of the same features, built on forecast::mstl -> stats::stl with
s.window = 11 for a single period. On the audit's 150-point random walk it gives F_S = 0.0865 (the
audit's quick check used s.window = "periodic", giving 0.0477; ROADMAP SC2's "about 0.05" is that
number). Both are low versus the old 0.96; the fixture pins the tsfeatures value.

Output: stl.rs, supsmu.rs, stl_strengths in stats.rs, r_stl_strength fixture family, seasonal_period
