# Phase 14: tsfresh Feature Parity - Context

**Gathered:** 2026-10-11
**Status:** Ready for planning

<domain>
## Phase Boundary

All 117 features returned by `ts_features` / `ts_features_by` / `ts_features_agg` match tsfresh on reference series, or carry a documented, intentional deviation. The work is in the shared Rust core (`crates/anofox-fcst-core/src/features.rs`) so every SQL surface inherits it. Requirements FEAT-01..FEAT-05. Audit input: `.planning/research/STAT-AUDIT-2026-10-08.md` §F (F1–F11) and §I (testing debt: value assertions against checked-in reference fixtures).

</domain>

<decisions>
## Implementation Decisions

### Parity contract and naming
- **D-01:** A checked-in mapping file (e.g. `validation/reference/fixtures/tsfresh_features/mapping.json`) maps each of the 117 feature names to its tsfresh calculator and exact parameters (or to a numpy/scipy reference expression). The fixture generator and the parity test both read it, so no feature can go unchecked.
- **D-02:** Features with no tsfresh counterpart (e.g. `range`, `linear_trend_r_squared`, `number_peaks_threshold_*`) are checked against a direct numpy/scipy reference, tagged `reference: numpy/scipy` in the mapping. This keeps the 117/117 coverage FEAT-05 requires.
- **D-03:** Features that currently differ from tsfresh (normalised permutation entropy, a different Lempel-Ziv algorithm, Benford ignoring |v|<1, etc.) are changed to match tsfresh exactly. A deviation is kept only where tsfresh itself is arguably wrong, and is then documented on the intentional-deviation list. No `*_normalized` duplicates; the count stays 117.
- **D-04:** Output changes are breaking changes, documented in the CHANGELOG with a before/after table. No compatibility flag (same pattern as Phase 13 D-04/D-08).

### Specific definitions
- **D-05:** skewness/kurtosis = pandas bias-corrected = scipy `skew(bias=False)` / `kurtosis(bias=False)`. This is identical to Phase 13 D-01, so `ts_stats` and `ts_features` agree.
- **D-06:** PACF lags 1–5 via Durbin-Levinson, matching statsmodels `pacf(method='ld')` (what tsfresh calls). Implemented in Rust core with no new dependency.
- **D-07:** FFT via `rustfft` (already in Cargo.lock transitively; WASM-safe) — make it a direct dependency of anofox-fcst-core, and run the WASM build check. `fft_coefficient` is unnormalised like numpy `rfft` and O(n log n). Spectral centroid/variance follow tsfresh `fft_aggregated` on the one-sided |rfft| spectrum.
- **D-08:** Entropy and complexity features copy tsfresh's own parameters and definitions, recorded in the mapping: `sample_entropy` (r = 0.2·np.std, ddof=0), `binned_entropy` (np.histogram bins), `permutation_entropy` (unnormalised, tsfresh dimension/tau), tsfresh's Lempel-Ziv algorithm, Benford on the first significant digit including |v|<1, `number_peaks` with tsfresh support semantics.

### Reference fixture and tolerance
- **D-09:** 6 seeded reference series generated by a checked-in Python script in the `validation/reference/python` uv project (tsfresh pinned there): white noise (n=200), random walk (n=200), seasonal AR(12) (n=144), trend + season (n=120), intermittent/many zeros (n=100), short (n=20). A constant series is checked separately as an edge case.
- **D-10:** Default tolerance `abs ≤ 1e-9 + 1e-9·|ref|`. Per-feature overrides are allowed only where floating-point evaluation order matters (FFT, regression), each with a reason in the mapping and the README.
- **D-11:** tsfresh NaN ↔ our NULL/NaN counts as a match. NaN against a number (either way) fails.
- **D-12:** Gate = a Rust integration test over the fixture JSON, so CI `cargo test` checks all 117 features, plus a SQL test that is NOT json-gated, sampling about 15 features through `ts_features` and `ts_features_agg` on the same series. The assertion count must visibly rise in `make test_release`. Phase 13 lesson: json-gated test files are skipped locally.

### Scope and SQL surface
- **D-13:** The feature set stays at 117 names. New tsfresh calculators are out of scope (deferred).
- **D-14:** Only the shared core changes. `ts_features` / `ts_features_by` / `ts_features_agg` signatures and the existing feature-params/config handling stay as they are.
- **D-15:** Docs: `docs/api/21-feature-reference.md` gets a "definition / tsfresh equivalent / deviation" column. The EDA skill (`plugins/anofox-forecast/skills/anofox-forecast-eda/SKILL.md`) and the CHANGELOG are updated, and stale "fix planned" notes are removed.
- **D-16:** Plan split along the success criteria: (1) fixture + mapping + harness tracer + PACF (FEAT-01); (2) derivatives, locations, time-reversal, agg_linear_trend rvalue, moments (FEAT-02); (3) FFT + spectral (FEAT-03); (4) entropies/complexity/peaks/Benford + the 117/117 assertion + docs (FEAT-04, FEAT-05). Every plan is checked by the same harness.

### Claude's Discretion
- Internal structure of the harness and mapping schema, fixture file layout, exact per-feature tolerance overrides (each justified), and whether ApEn in `ts_features` shares the Phase 13 Pincus implementation.

</decisions>

## Specific Ideas

- ROADMAP anchors: `sample_entropy` ≈ 1.099 on the reference series (previously 0.981). PACF lags 3–5 must no longer reuse the lag-2 formula. `mean_second_derivative_central` gets the ½ factor. `last_location_of_*` uses (idx+1)/n. `agg_linear_trend` rvalue is signed.
- The same DoD as Phase 13: `cargo fmt --check`, `cargo test --workspace`, `RUSTUP_TOOLCHAIN=1.89.0 GEN=ninja make release`, `make test_release`, snippet harness 0 FAIL, and a WASM build check because of the new direct rustfft dependency.
