<objective>
Replace the fixed-coefficient "ARIMA" with a real crate ARIMA/SARIMA fit driven by new
`arima_order` / `seasonal_order` parameters (D-08, D-09), make the FFI option parsing strict
(no UTF-8 → "auto" fallback, no silently dropped seasonal-period entries — D-07), plumb the two
new keys through every C++ forecast entry point, make the aggregate/CV surfaces NULL-safe for
models without bounds (D-02), build the extension once and pin the SQL-level results for
FCST-01/02/03/04 in a new natively-run sqllogictest.

Purpose: FCST-04 (and the FFI-parsing half of FCST-06; SQL-level proof of 10-01's FCST-01/02/03).
Output: crate ARIMA path, strict FFI parser, new R fixtures + Rust tests, C++ param keys, SQL test.

Encoding decision (orchestrator delegated to planner): the two orders travel through the FFI as
NUL-terminated strings in appended `[c_char; 32]` fields (`arima_order_str`, `seasonal_order_str`),
mirroring the existing `seasonal_periods_str` precedent. The empty string is the explicit "unset"
sentinel, which keeps `ARIMA(0,0,0)` expressible and keeps the ABI additive (fields appended after
`ensemble_method`; C++ callers memset the struct, so unset = empty). Parsing and bounds-checking
live once in Rust core.
</objective>
