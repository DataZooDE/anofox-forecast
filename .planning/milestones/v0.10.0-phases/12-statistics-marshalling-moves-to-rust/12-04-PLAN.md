<objective>
Bring the conformal and bootstrap scalars onto the Phase 12 contract: shared list reader (D-01),
validity through the FFI with Rust applying the policy (D-02), and Rust-side validation that per-step
conformal residual counts are a multiple of the horizon (D-10, ROADMAP criterion 5 first half).
Phase 16 (CONF-01..05, RUST-04) depends on exactly this: "shared list helper and pairwise-complete
validity in the conformal scalars". Do NOT change interval formulas, quantile definitions, horizon
ordering in macros, or the asymmetric/adaptive/jackknife methods — those are Phase 16.

Policy classes (recorded here so every call site applies the same rule):
- Paired inputs (coverage/evaluate: actual-lower-upper; mean_interval_width: lower-upper; per-step:
  fold forecast-actual per step) -> missing::complete_cases (pair dropped if any side NULL/NaN).
- Residual pools (residuals[] of quantile/predict/asymmetric/learn/bootstrap) -> missing::drop_missing
  (a NULL residual is an incomplete (actual, fitted) pair, so dropping it IS pairwise-complete).
  NaN residuals are treated as missing by the phase-wide NaN = NULL rule; Phase 16 CONF-03 still owns
  the full split-conformal finite-sample/NaN contract.
- Forecasts that intervals are built around -> position-preserving: compute with the missing
  positions set to a 0.0 placeholder, then missing::propagate_missing writes NaN into point/lower/upper
  (and per-step half_widths are unaffected) at exactly those positions; C++ writes NaN as SQL NULL.
- Parameter lists (alphas, quantile levels, calibration-profile arrays) -> ReadNoNulls error in C++
  (malformed argument, not data).

Execution environment: worktrees disabled — branch `fix/statistical-correctness`, main tree; reuse
`build/release`; ONE full build in Task 3; Tasks 1-2: cargo tests + compile-only ninja object checks.
</objective>
