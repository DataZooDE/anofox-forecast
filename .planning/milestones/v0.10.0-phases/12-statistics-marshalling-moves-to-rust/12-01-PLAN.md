## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| C++ scalar function -> Rust FFI | values pointer + validity bitmask + length cross the ABI; Rust trusts only `length` |
| SQL caller -> C++ list reader | arbitrary LIST(DOUBLE) vectors (flat / constant / dictionary, NULL elements, empty lists) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01 | Tampering / DoS | metric FFIs reading `*_validity` | high | mitigate | Rust reads exactly `len.div_ceil(64)` words via the existing `build_series` (never a caller-supplied word count); the C++ reader allocates exactly `(n+63)/64` words for the same n it passes as the length |
| T-12-02 | DoS | Rust panic on degenerate input crossing the C ABI | medium | mitigate | every modified FFI keeps its `catch_unwind(AssertUnwindSafe(..))` + `check_null_pointers`; empty lists pass `nullptr` validity and hit the existing null-pointer/InsufficientData paths (no `from_raw_parts` on a null pointer) |
| T-12-03 | Tampering | ListDoubleReader indexing constant/dictionary vectors | high | mitigate | all element/row access goes through `UnifiedVectorFormat.sel->get_index` on both list and child vectors; SQL test covers constant, cross-joined and constant-NULL list arguments |
| T-12-04 | Repudiation (data integrity) | silent NULL splicing misaligning pairs | medium | mitigate | this plan's deliverable: pairs dropped by an explicit, tested Rust rule; documented in docs + CHANGELOG |
</threat_model>
