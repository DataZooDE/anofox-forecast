<objective>
Implement D-03/D-04 for single-series analyses: one Rust-owned gate (trim leading/trailing NULLs,
error on interior NULL naming the 1-based position, empty -> NULL) exposed through the FFI and wrapped
by the shared C++ reader, then route every diagnostic (diagnostics.cpp), period estimator
(ts_periods.cpp) and seasonality function (ts_seasonality.cpp) through it. Also make every argument of
the touched functions — list AND scalar parameters — read per row via UnifiedVectorFormat (RUST-01):
today a constant `period` / threshold argument is read with `FlatVector::GetData(...)[row_idx]`, which
returns garbage for rows > 0 of a chunk when the argument is a constant vector.

Purpose: ROADMAP criterion 1, second half ("single-series diagnostics given interior NULLs error or
report explicitly instead of splicing"). Plan 12-03 applies the same gate to the remaining detection
functions and the features aggregate.

Policy notes recorded for the executor (Claude's discretion, decided here):
- Position k in "interior NULL at position k" is the 1-based position in the caller's ORIGINAL list
  (SQL list indexing), as produced by missing::trim_edges_reject_interior (plan 12-01). NaN counts as
  NULL (Phase 10 convention).
- Outputs describe the trimmed series (Phase 10 precedent: fitted arrays were trimmed-length). These
  functions return scalars/period lists, so no positional output changes here.
- Too-short-after-trimming series keep each analysis's existing behaviour (its own FFI error -> NULL).

Execution environment: worktrees disabled — branch `fix/statistical-correctness`, main tree.
Reuse `build/release`; ONE full build in Task 3 (Tasks 1-2: cargo FFI tests + compile-only ninja
object checks in the same tree).
