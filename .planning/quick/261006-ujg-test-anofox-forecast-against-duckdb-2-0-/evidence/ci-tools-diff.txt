### release / test_release_internal
- `test_release_internal`, `test_debug_internal`, `test_reldebug_internal` targets are GONE.
  `test_release` now calls a `RUN_TEST` macro that prefers
  `python3 ${DUCKDB_SRCDIR}/scripts/ci/run_tests.py ./build/release/test/unittest $(T)`
  if that runner script exists in the duckdb submodule, else falls back to invoking
  `./build/release/test/unittest $(T)` directly (empty TEST_RUNNER).
  `T` defaults to `"${TESTS_BASE_DIRECTORY}*"` i.e. `"test/*"`.
  Action taken: Task 2 runs `./build/release/test/unittest "test/*"` directly (bypassing
  `make test_release_internal`, which no longer exists), matching what RUN_TEST falls back to
  when the new run_tests.py runner isn't present. This preserves identical test selection/output
  format to the v1.5.5 baseline (same unittest binary, same glob).
- `TEST_PATH` changed from `"/test/unittest"` (leading slash, quoted) to `test/unittest`
  (no leading slash, unquoted) — purely a macro concatenation convention, no behavior change
  for the direct-binary invocation path above.
